# AreYouIn MVP Plan

This MVP plan starts with a hello-world-first greenfield build, then incrementally turns the source concept into a persistent shared simulation loop grounded in structured state, immutable history, and narrative memory.

## Stages

- [Stage 01: Hello World And Stack Lock](stage-01-hello-world-and-stack-lock.md) - active stage; 2 units ready now.
  Establish the executable foundation before scaffold work: lock the initial stack, then create the smallest running app surface that proves the chosen runtime can start cleanly.
- [Stage 02: Scaffold And Baseline App](stage-02-scaffold-and-baseline-app.md) - directional stub; later units will be added incrementally.
  Create the first runnable application shell using the locked stack, with repository hygiene, local scripts, and a committed hello-world route that proves the app can boot.
- [Stage 03: World Entry And Choice](stage-03-world-entry-and-choice.md) - directional stub; later units will be added incrementally.
  Build the first playable entry path: a public-facing simulation entry surface, the ASI premise, and persisted YES or NO path selection for a player.
- [Stage 04: Canonical State And Event History](stage-04-canonical-state-and-event-history.md) - directional stub; later units will be added incrementally.
  Introduce the structured Convex model for authoritative world and player state, plus append-only events for meaningful changes before any LLM-mediated consequences alter reality.
- [Stage 05: Natural Language Action Loop](stage-05-natural-language-action-loop.md) - directional stub; later units will be added incrementally.
  Connect player action input to an LLM interpretation boundary, deterministic adjudication guardrails, persisted state changes, event logging, and grounded narrative response.
- [Stage 06: Narrative Memory](stage-06-narrative-memory.md) - directional stub; later units will be added incrementally.
  Add markdown-backed world memory updates for significant events while preserving the rule that wiki summaries explain the world but do not own numeric or enforceable truth.
- [Stage 07: Daily Progression](stage-07-daily-progression.md) - directional stub; later units will be added incrementally.
  Implement the one-real-day to one-in-game-day progression path, including durable snapshots, global changes, and return-player continuity across sessions.
- [Stage 08: MVP Hardening And Commit Flow](stage-08-mvp-hardening-and-commit-flow.md) - directional stub; later units will be added incrementally.
  Tighten verification, persistence checks, failure recovery, and local commit behavior so successful scaffold and implementation runs are staged and committed while pushes remain explicit user decisions.
