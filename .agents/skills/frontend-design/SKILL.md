# Frontend Design

Use this repo-local product skill when the task is clearly about generating or materially redesigning frontend UI.

## Workflow

1. Ground the work in the real product, audience, and constraints before choosing visuals.
2. Pick an intentional aesthetic direction instead of defaulting to generic app UI.
3. Build real working frontend code using the repo's established stack and primitives.
4. Add polish through typography, spacing, color, layout, and motion where it helps the product feel designed rather than generated.

## Core Rules

- Make the interface feel specific to the product rather than interchangeable.
- Use a clear visual point of view and carry it through the whole surface.
- Prefer coherent typography, color tokens, and spacing systems over one-off styling noise.
- Respect the existing design system when the task is a narrow extension or cleanup inside an established UI.
- Push harder on aesthetics when the task is a new page, screen, component set, dashboard, onboarding flow, landing surface, or explicit visual-polish pass.
- For landing pages, make the above-the-fold section do the real work: one specific headline, one supporting subheadline, one primary CTA, one hero visual or explicit copy-only fallback, and enough negative space to keep the first scan effortless.
- Prefer specificity over cleverness in landing-page headlines and CTA labels.
- Use visual proof when it exists, and do not bury the first screen under extra cards, badges, or competing actions.
- Keep the next scroll simple too: a sharp problem statement, a clear 3-step how-it-works section, and a benefit-led evidence section before anything more expansive.
- Avoid generic AI-slop patterns such as timid palettes, repetitive card stacks, default system-font-heavy layouts, and purple-gradient-on-white defaults.
- Keep accessibility, responsiveness, and production-readiness intact while refining the design.
