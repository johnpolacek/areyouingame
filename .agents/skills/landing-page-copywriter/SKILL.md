# Landing Page Copywriter

Create landing page copy that is sharp, believable, and easy to build into a clean page.

## Default Approach

Use StoryBrand or PAS, but keep the result calm and focused.

The goal is not to generate the largest possible marketing page. The goal is to make the page immediately understandable, credible, and conversion-oriented without becoming cluttered.

## Workflow

1. Ground yourself in the real product first.
   - Read the project docs, PRD, README, existing positioning, and `wiki/sources/marketing-brief.md` when present before asking for missing details.
   - Ask only for high-impact missing facts that are not discoverable locally.
2. Define the essentials:
   - product
   - audience
   - problem
   - differentiated value
   - desired action
   - real proof available, if any
3. Choose a compact page narrative:
   - Above the fold
   - Problem
   - How it works
   - Feature benefits
   - Proof
   - Final CTA
4. Write copy that supports a clean implementation, not a feature dump.

## Core Rules

- Treat the above-the-fold section as the primary contract: one clear headline, one supporting line, one primary CTA, and one hero visual or explicit copy-only fallback.
- If `wiki/sources/marketing-brief.md` exists, treat its `Above The Fold`, `Problem`, `How It Works`, `Feature Benefits`, and `Minimal Page Shape` sections as the default contract unless the user explicitly changes direction.
- Prefer 5-6 meaningful sections over a sprawling page.
- Focus on outcomes and workflow clarity before feature enumeration.
- Use concrete language instead of stacked startup jargon.
- Do not invent testimonials, logos, metrics, pricing, guarantees, or urgency.
- If no social proof exists, use honest credibility instead:
  - open source
  - local-first
  - built for a specific audience
  - clear workflow explanation
- Do not force FAQ, pricing, or social-proof sections if the product is too early for them.
- Avoid generic CTA text like `Learn More` or `Submit`.

## Anti-Clutter Rules

- No giant feature grid on the first pass.
- No wall of badges.
- No more than one CTA above the fold unless the project docs explicitly justify more.
- No FAQ, pricing, or testimonial wall unless the project docs provide real support for them.
- No repeated restatement of the same value proposition in every section.
- No unsupported superlatives such as `world's first` unless the user explicitly wants and can support that claim.
- No filler copy written only to make the page longer.

## Recommended Section Shape

### Above The Fold

- headline: 10 words or fewer when possible
- subheadline: 1-2 short sentences
- primary CTA only
- hero visual: real screenshot, illustration, or demo cue when available
- explicit copy-only fallback when no real asset exists yet
- preserve negative space so the first screen reads in one scan

### Problem

- describe the pain in 2-4 short paragraphs or bullets
- make the cost of the current workflow clear
- aim for a quick "yes, exactly" reaction from the reader

### How It Works

- 3 simple steps
- each step should explain a real user action and outcome

### Feature Benefits

- 3-6 focused points
- lead with the user benefit, then use the feature as evidence
- keep it outcome-first instead of drifting into a raw feature list

### Proof

- use only real trust material
- if proof is thin, keep this section minimal instead of inventing weight

### Final CTA

- restate the outcome
- ask for one clear next action

## Output Guidance

When the user wants raw copy, provide:

- page narrative
- one strong default headline plus a few lightweight fallback options only when useful
- section copy
- CTA options
- brief implementation notes

When the user is building the page itself, write copy that can drop directly into the implementation without adding decorative filler.

## Quality Bar

Good landing page copy should feel:

- clear before clever
- specific before broad
- paced rather than crowded
- credible rather than hype-driven
- useful to both the designer and the implementer
- strongest above the fold before anywhere else on the page
